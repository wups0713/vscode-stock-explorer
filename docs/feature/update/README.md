# 功能需求：自動輪詢與狀態更新 (Update Stock State)

## 1. 功能描述與目標

本功能實現股票資料的自動輪詢與即時更新，並在更新過程中於股票視圖 (TreeView) 上方提供明確的載入進度條 (Loading Bar / Progress Indicator) 視覺回饋。僅在股票視圖容器 (View Container) 處於聚焦/可見狀態時，依據使用者在 `settings.json` 設定的秒數週期性發送網路請求更新行情數據，降低系統資源消耗並避免 API 頻率限制。

## 2. 使用者價值與背景

即時的股價變動是股票追蹤的核心需求。網路 API 請求受環境與回應時間影響，在數據更新期間（包含首次載入、手動刷整與背景輪詢）顯示視圖上方載入進度條，可提供使用者清晰的操作狀態視覺回饋，避免使用者誤以為介面凍結或反應遲鈍，大幅提升整體使用體驗。

## 3. 功能需求清單

- **設定項目（Configuration）：**
  - 設定鍵名：`stockExplorer.updateInterval`
  - 資料型別：數字（Number，單位為秒）
  - 預設值：`15`
  - 特殊限制：當設定值為 `0` 時，視為停用自動輪詢功能。
- **載入進度條（Loading Progress Indicator）：**
  - 於股票視圖 (TreeView) 上方顯示載入進度指示器。
  - **涵蓋所有更新情境：**
    1. **視圖切換首次更新：** 使用者切換至股票 TreeView (視圖變為可見) 觸發首次資料更新時顯示進度條。
    2. **手動重新整理：** 使用者點擊標題列「重新整理按鈕 (Refresh Action)」時顯示進度條。
    3. **背景自動輪詢更新：** 每隔 `updateInterval` 秒背景觸發輪詢拉取數據時顯示進度條。
  - **生命週期管理：**
    - 數據更新請求啟動時顯示載入進度條。
    - 數據更新完成（無論請求成功或失敗/異常捕獲處理完畢）後，必須確保隱藏/關閉進度條。
- **視圖狀態感應與輪詢控制：**
  - 使用者切換至股票 Tree View（View 變為可見）：
    1. 立即觸發一次即時數據更新（並顯示載入進度條）。
    2. 若 `updateInterval > 0`，啟動定時器（Timer），每隔 `updateInterval` 秒輪詢一次（每次更新均顯示載入進度條）。
  - 使用者切換至其他 Tree View 或隱藏側邊欄（View 變為隱藏）：
    1. 立即清除並停止定時器。
    2. 停止背景輪詢。
- **手動刷新支援：**
  - 提供手動重新整理按鈕（Refresh Action），使用者可隨時立即更新數據（顯示載入進度條），且不影響自動輪詢計時。

## 4. 主要使用場景與範例

- **場景 A：開啟側邊欄自動更新與進度顯示**
  - 使用者點開股票總覽側邊欄，系統立即拉取最新股價，視圖上方顯示載入進度條，更新完畢後進度條消失，並依預設 15 秒間隔自動刷新畫面。
- **場景 B：手動重新整理行情**
  - 使用者點擊視圖標題列的重新整理按鈕，視圖上方出現載入進度條，數據拉取完成後畫面更新並關閉進度條。
- **場景 C：背景自動輪詢進度提示**
  - 達到輪詢週期（如 15 秒）時，系統在背景自動觸發更新，視圖上方短暫顯示載入進度條完成更新。
- **場景 D：切換視頁省電與網路資源**
  - 使用者切換回檔案總管（Explorer），股票輪詢定時器立即停止，避免在背景繼續發送 API 請求。
- **場景 E：停用自動輪詢**
  - 使用者將 `stockExplorer.updateInterval` 設為 `0`，視圖僅在開啟時或點擊「重新整理」按鈕時進行手動更新（更新時均顯示載入進度條）。

## 6. 約束條件與限制

- 載入進度條控制需適當整合 VS Code 原生 TreeView 的 progress 顯示機制。
- 更新作業結束時（包含成功取得資料或拋出/捕獲 Exception 時），必須確保載入進度條終止，防止視覺提示無限殘留。
- 輪詢機制必須嚴格依據 VS Code TreeView 的可見性事件（`onDidChangeVisibility`）觸發與終止。
- 網路請求例外或 API 異常時應具備容錯處理，避免輪詢崩潰。
